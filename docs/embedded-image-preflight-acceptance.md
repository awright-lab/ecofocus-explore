# Embedded image readiness — goal36 partial improvement

Export preflight now offers an explicit **Check embedded images** action. It checks every visible image object and image page background across the report. Failures identify the page and object; successfully decoded placements are grouped separately. It does not alter assets, save the report, download a file or start an export.

Only embedded base64 PNG, JPEG and static WebP are decoded. External URLs, SVG and empty content are reported as unverified without fetching them. PNG animation headers and animated WebP are refused; JPEG orientation may swap the decoded dimensions. PNG must reach its first IDAT header and JPEG must expose a supported frame header within the bounded prefix. Unusual but valid files outside these constraints are unverified, not declared corrupt. Header inspection is not file validation; success additionally requires the browser's load and decode operations and compatible positive dimensions.

The check supports at most512 placements,64 exact distinct sources,8 Mi-characters per source and32 Mi-characters of distinct source content. It reads at most64 KiB of header before decoding and rejects declared dimensions over8,192 per side or16 million pixels. Sources decode serially, once per exact data URL, with a five-second timeout each. These are conservative check limits, not a universal browser memory guarantee or a new report-save/export limit. Cancellation and unmount release handlers, timers and decoder sources. Browser decoding can internally continue briefly after cancellation; its late completion cannot publish a receipt.

Results belong to the captured image inventory, including page/object identities, names and exact image strings. Changes during or after a check invalidate its results. Inspection is read-only and temporary; closing/reopening requires a fresh check. Keyboard focus stays on the initiating control while checking; repeat activation is guarded, and Cancel restores that control's focus. When completion or a source change removes Cancel, focus returns to the check button only if Cancel held focus immediately before removal. Focus held elsewhere stays there. Four follow-up component regressions verify both ownership cases and avoid stealing focus during background completion.

## Verification and scope

Model/component tests cover supported headers, eight actual synthetic images independently generated and decoded with Pillow, malformed/animated/oversized sources, all budget limits, exact deduplication, serial work, dimension mismatches, decode failure/unavailability/timeout, cancellation/cleanup, source changes and modal focus ownership. Browser decoding is controllably simulated in these tests. A real App test opens the actual Export-menu preflight with a synthetic1,000-row by30-field study and two report pages. It checks valid shared images, broken and external sources, closes and cold-remounts, and verifies original studies/report drafts and absence of live fetches. This is jsdom acceptance, not a native browser check.

Consult the checkpoint evidence for final suite/type/build results. Goal36 remains partial: native browser decoding and visual acceptance, broader PowerPoint/Excel checks, final format rendering, clipping/color/font fidelity and Office/download acceptance remain open. A decoded-image receipt is not export approval and does not assert that all other preflight checks pass. Export behavior is unchanged. The prior denied native socket, upload and PR-description actions were not retried.
