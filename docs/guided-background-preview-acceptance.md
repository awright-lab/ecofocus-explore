# Background previews for larger local studies

Create analysis previously ran the complete imported query while rendering the dialog, including every change to a field, calculation or output. For complete browser-local studies with5,000or more source rows, the dialog now waits for **Calculate preview in background**. Preparation copies only selected raw columns in250-row batches, then a dedicated module worker uses the existing calculation engine. Preparation shows actual row counts; calculation is indeterminate rather than a fabricated completion percentage. Canceling terminates the worker. Its single persistent action button retains focus when changing between calculate/cancel/recalculate states, and completion has an accessible status message.

Small-study immediate previews and illustrative sample/server behavior are preserved. A larger-study preview is optional: failure or unavailable worker support has an explicit message, and fresh creation remains available after the preview has finished or been canceled. **Creating still executes the existing complete original-source query and can take time on the main thread.** Preview data never substitutes for that calculation or enters report tiles, history, saved workspace, exports or local execution receipts. Source preparation, selected-value verification, filtering choices and transport cloning still involve main-thread work. This feature does not make the whole authoring journey run in background workers.

The temporary worker projection contains selected field metadata and raw values (including their sample/value labels), at most four fields. Dataset/file/connection headers, unrelated columns and full workspace/report objects are excluded. Its synthetic source identity is deliberately distinct from the original dataset; it cannot serve as a persisted source or provenance receipt. There is no fetch or service request. The calculation uses complete rows, never a sample, and applies the original grouping, optional measure, breakout, single filter and all-respondent numeric scope. Saved audiences are not silently added to this guided preview.

Limits:1–50,000complete local-file rows for the worker job (the UI selects it at5,000),2MiB selected metadata,20MiB encoded selected values,20,000characters per raw value,5,000result cells, a4Mi-character bounded JSON result checked before transport and on receipt, and a30-second calculation timeout timer. Unfiltered raw categories plus declared labels conservatively bound output, so a preview may refuse a case that filtering or numeric-code aliases would reduce. No category, row or cell is silently trimmed. Input and response budgets bound application-owned structures, not total browser heap, native decoder allocation, CPU time or background-tab scheduling. Higher-row-count creation remains on its existing path; preview refusal does not validate its memory or save capacity.

Preparation snapshots selected fields/settings and compares the copied values against the current study before starting a worker and accepting its response. Changed settings, import identity, selected metadata, row array or selected raw values cancel/revoke the preview; pending old results cannot paint alongside a replacement source before effect cleanup. A transient changed-and-restored row cannot create an accepted mixed projection. Unselected field changes do not establish a new calculation and are not authenticated. The UI keeps the selected field-launch snapshot stable across progress renders. A missing worker, blocked constructor/post, runtime/decoding error, timeout, unsupported/partial input or mismatched response produces no synchronous preview fallback and no save.

Verification covers original-engine equivalence for count, percent, sum, mean, filters, case-insensitive raw keys and explicit all-respondent numeric scope; source/setting/metadata/import changes; batch and active cancellation/late completion; byte/metadata/cell caps; worker failures; and accepted-preview revocation. Dialog tests check no large calculation on render, retained small previews, same-node focus, source ownership before passive cleanup, unavailable browser support, fresh creation from the original source and field-launch/unmount lifecycle.

The actual App test uses5,000×5synthetic data and the real importer, query engine, editor/history and workspace writer. It checks that previewing changes no saved report/study, creates a fresh original-source analysis on a separate page, retains the original page and source, excludes the preview identity from saved JSON and cold reopens the result intact. Its worker is controlled for UI testing; jsdom/dialog/ResizeObserver helpers are not native browser verification.

Separate Node worker_threads checks run the **actual browser worker entry**, with only the message transport adapted. Five1,000-row scenarios plus50,000×30source data match the original engine; only four selected fields cross the worker boundary. Independent Python integer/Fraction arithmetic checks all resulting counts, bases and values. Heartbeats continue during preparation and worker calculation, cancellation terminates the actual worker, and source hashes remain unchanged. This is an offline worker/transport acceptance, not browser Worker loading, CSP, mobile responsiveness, frame-rate or production performance acceptance.

Original goal15 remains partial. Native browser/CSP/accessibility/low-memory/visual acceptance, broader query workflows, filter enumeration, full million-row import/analysis/save/export and transactional storage/capacity remain open. No engine/statistical method, persistence schema, production data, credentials, permissions, billing or security setting was changed. Nothing is merged or deployed by this candidate.
