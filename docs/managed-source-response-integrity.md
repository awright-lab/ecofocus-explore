# Preserve work across managed-source checks

A source check must not replace the workspace captured before an asynchronous server request. Four actual-App regressions reproduced the previous behavior: after saving a separate 1,100-row/30-field recovered study, an older readiness/field-inspection response (success or failure) rewrote the earlier workspace and removed the newly saved study. The recovery queue had already acknowledged it. Tests use fabricated data and mocked endpoints only.

Readiness and field inspection capture the workspace, pending-save identity, route, requested source metadata and exact saved-version text. Results apply only while those inputs remain current and the screen owns the request. Readiness also binds the selected provider. A provider-selector change alone can still permit a bound inspection save when its source and workspace remain unchanged; feedback for the changed provider view is suppressed. A newer workspace, relevant source mapping, pending save, saved version, route, unmount or newer request invalidates the response. A different pending workspace from the one displayed blocks the check before any network request, preserving recovery work not yet reflected in Home. This is strict refusal, not a field-level merge. An unrelated edit can therefore require checking again; it preserves newer work rather than guessing how to merge it. Saved-version checks also cover the interval before React commits new props and sequential writes from other tabs. They do not make localStorage comparison/write atomic.

Replies must match the requested provider, connection and source/path/type. The1MiBplainJSONmetadata budget is checked after response.json() has parsed the reply; it does not bound transport bytes or parsing memory. Statuses, timestamps, diagnostic lists and dense unique field IDs/raw names are checked before application. Inspection continues to request at most200fields; this does not establish complete remote discovery. A malformed or empty successful inspection cannot silently replace prior field definitions. A failed inspection records its failure while retaining the old fields and authored roles; its failed status blocks saved-definition readiness until another successful inspection. Successful schema refresh retains the existing replacement semantics; general authored-role reconciliation across changing schemas remains separate work.

The actual save acknowledgement controls success feedback. Failed writes keep the exact additive/current candidate for recovery without replacing a newer pending operation. Generic retry can save that candidate and update its feedback. The tested older rejected-acknowledgement path preserves newer pending/UI work and does not announce results on another screen. The late failed-save fallback still needs a saved-version recheck and regression for an independently changed saved copy without a newer UI/pending reference before any asynchronous writer is activated. The active synchronous writer does not establish that future guarantee. Server error diagnostics remain available. Source results are local metadata; server readiness is not proof of live Snowflake calculations or credentials.

No endpoint, credentials, permissions, database, billing or connection configuration is changed by this correction. Requests and their existing limits are unchanged. Ignoring an obsolete response does not cancel work already started on a server and does not promise a query-cost abort. Live services, native browser/OS file handling, crash recovery and simultaneous-tab atomicity remain unverified. The active writer is still localStorage; durable storage/restore activation remains gated. Original goals1and7remain partial. No publication, merge or deployment is included.
