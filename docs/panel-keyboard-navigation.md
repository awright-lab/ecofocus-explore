# Protect tool controls and close-panel navigation

The actual Studio rail and the tool panel close button were outside the existing canvas shortcut guard. With a report object selected, Delete or Backspace on those controls could remove that object and save the changed report. The rail and complete tool-panel container now use the same control-owned keyboard scope as the header, inspector and inline editors. Native control/browser behavior remains available; canvas authoring keys still work when they belong to the canvas.

Explicit Close tool panel returns still-owned focus to the corresponding Studio tool. Explicit Close properties returns it to Toggle properties. Close buttons stay connected inside hidden containers, so a small separate hook checks original ownership and actual panel hiding at commit. Blur cancels the request. Newer outside focus, unfocused programmatic clicks, missing/disabled/hidden/inert destinations and still-visible panels do not receive a focus override. No timer or forced modal restoration is involved.

The preserved parent regressions are included in the source suite. Their lazy Pages-tree readiness condition is explicit; all exact source/workspace/cold-reopen assertions remain. The study is still1,000rows by30fields; its canvas uses a single-cell average rather than a2,000cell table, avoiding irrelevant rendering and huge failure diffs. A tile-equality assertion is added before the existing whole-save assertion. An initial wide-fixture run hit out-of-memory before valid execution; that run is not counted as reproduction. The valid current-code run reaches both checks and demonstrates saved analysis removal.

Six actual App/jsdom panel cases verify control-owned keys, ordinary close handoffs, deliberate outside focus/blur, saved study/report preservation and two cold-reopen paths. A seventh checks positive canvas nudge and keyboard Undo. Nine small React harness cases check ownership and destination conditions. All data is synthetic; Date alone is fixed while real autosave and UI timers run. Existing export focus and layout workflows remain regression gates.

This is scoped work toward goal16, not general accessibility completion. Native browser automatic blur when hiding a focused button, actual OS keys, fullscreen, screen readers, touch and visual acceptance remain unverified. No storage schema, writer, report mutation command, export renderer, analysis, permission or security-setting change is included. Existing export navigation ownership checks remain intact.

The first complete run exposed26existing failures in two files whose editing setup dispatched authoring keys from Create analysis, or whose isolated negative control removed only the inner sidebar guard. Setup now explicitly focuses the body for intended canvas editing; all original focus, data, history and recovery assertions remain. The negative control verifies that the outer tool-panel scope still protects content, then temporarily removes both scopes to reproduce the old handler and Undo it, restoring markers in finally. An AST comparison retains all338original assertion statements unchanged in order, adding three ownership assertions. No production guard was relaxed to satisfy these tests.
