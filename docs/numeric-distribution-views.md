# Numeric distribution views

Numeric field inspection now offers response counts, percent of valid numeric values, and cumulative percent. Counts remain the default. The percentage scale is fixed at0–100; cumulative bars include the current range and every preceding range, finishing at100% only when complete counts sum to the valid base. This is an unweighted descriptive distribution, not a confidence interval, causal result, survey-adjusted estimate or a saved report chart.

All three views use the existing profile's numeric bins; binning and source parsing are unchanged. Percentages are derived from integer counts and valid-value denominator without early rounding. The complete range table includes counts, percentages and cumulative percentages with a field-specific caption. Every bar has range, count/base and mode context; chart descriptions explain cumulative meaning. Blank and invalid numeric values stay outside the denominator. Existing percentage formatting preserves a small nonzero share and a partial share near100 rather than labelling them0or100. Rounded displayed shares need not sum to100.

The view model requires dense contiguous ranges, finite boundaries, exact safe integer counts, correct last-range inclusion and a complete total matching the valid base. Invalid metadata is withheld rather than represented as trustworthy percentages. This is structural/count consistency checking, not independent recalculation of profile bins or protection against arbitrary JavaScript proxies. Runtime worker validation remains separate.

Changing view is temporary UI state. It does not write workspace settings, change the source study, modify existing analyses or replace historical caches. Returning after a component remount starts with counts. If invalidation removes a focused selector, the stable distribution container receives focus only when that removed control owned it; deliberate outside focus or blur is preserved. Parent field/source changes retain existing lifecycle and refresh rules; background snapshots require explicit refresh for later same-reference value changes.

Tests cover exact fractions, one-in50,000, constant and endpoint values, zero-count gaps, exclusions, invalid totals/bounds/metadata and accessor refusal; interactive axis/description/table/mode agreement; selected-field updates and conditional focus. Actual-App coverage uses a1,000-row synthetic study, all ten known range counts/percent/cumulative values, shortcut protection and exact source/draft/published-snapshot preservation through same-process reopen. Browser Worker, native keyboard/assistive technology, touch, scrolling, visual layout, Office, downloads and persistent report-distribution charts remain unverified or outside this batch. No production build is attempted after the prior EPERM. Original goal31remains partial; no publication, merge or deployment.

## Expanded-control focus correction

The view selector, range-table summary and keyboard-focusable table region each register focus ownership before removal. If the mounted distribution becomes unavailable, only removal of the still-focused control can move focus to the persistent distribution container, and only when focus has fallen to the document body. Deliberate outside focus and explicit blur are preserved. A fallback inside a hidden or inert panel is excluded. This is local to the distribution; the shared removed-control hook and other profile components are unchanged. Removing the whole parent component remains a separate lifecycle/acceptance boundary.

Regressions exercise summary and expanded-table removal under owned, outside and explicit-blur focus, retain the selector cases, and check newly hidden/inert panels do not receive fallback focus. The pre-correction tests reproduced both missing ownership cases and hidden/inert fallback defects. DOM tests do not establish native browser focus, screen-reader or touch behavior.
