# Searchable recode values beyond the first 500

The preparation recode picker previously derived all current codes but silently displayed only the first 500. The revised picker pages every supported exact raw code (50 per page), offers literal escaped-JSON substring or whole-display search, and keeps selected codes visible and removable even when their page or search is hidden. Searching and paging change only the picker view, not preparation history, dirty choices, previews or saved data.

Values are derived after applied transformations, with the original case-sensitive string semantics and sort order. Empty strings, whitespace, CR, LF, CRLF, backslashes and numeric-looking text remain distinct. Empty codes display as the escaped JSON string `""`, distinct from a literal `[blank]` code. Whole escaped-display matching compares the canonical JSON string shown in the picker; it does not interpret alternative escape spellings. Source row values are never normalized by search. Codes longer than the version-1 recipe limit of 512 UTF-16 code units are counted and explicitly not offered for selection; existing studies are unchanged. At most 100 exact codes can be selected for one step. A hundred selections remain visible, and the 101st is refused before preview instead of dropping an existing choice.

The complete supported catalog is bounded at 50,000 incoming codes and 4 Mi UTF-16 units of escaped display text. If the aggregate budget is exceeded, the picker refuses the whole list and retains existing choices rather than exposing a misleading subset. Distinct sorting, filtering and catalog construction remain synchronous; native memory, responsiveness and low-resource acceptance are unverified. This is not a background preparation implementation or a general large-source guarantee. Existing complete-local preparation limits, explicit preview, source fingerprints, immutable separate-copy save, Undo/Redo and recovery are unchanged. Same-reference external source mutations are not newly monitored by the code catalog; preview/replay continue to check the source using existing rules.

Focus is retained on persistent pager controls. Removing a focused selected-code button moves focus to the selected-code heading; replacing a focused visible code moves focus to search. Whole-picker removal returns owned focus to the persistent preparation dialog. These paths recheck ownership and leave deliberate outside focus or blur alone. Native pointer, screen-reader, touch and visual behavior remain unverified.

Verification includes all 50,000 supported codes across 1,000 pages, exact and substring lookup, escaped line endings/quotes/empty strings, raw numeric aliases, own prototype-like strings, recipe limits and whole-list refusal. Components cover cross-page and filtered selections, cap refusal/replacement, unknown restored choices, and inside/outside/blur focus ownership. An actual App synthetic 1,000-row workflow selects the first and last codes, keeps selections through filtering, saves a recovery checkpoint, previews exactly two changes, applies/Undo/Redo, encounters a simulated quota refusal, retries the additive save, and reopens both saved history and unfinished checkpoint in the same process. Original study, complete report records and published snapshots are compared exactly. Full rows/metadata in the new prepared copy remain exact; the existing writer intentionally compacts its representative preview from 50 to 25 rows. No respondent rows are removed. No real respondent data, network or native quota/crash test is used.

This is scoped progress toward reversible preparation, not full original goal 11 closure. Independent review is pending. The previous 85-file proposal, checkout, stale index and all frozen backups remain separate and unchanged. No publication, merge, production deployment or retry of the blocked build is part of this change.
