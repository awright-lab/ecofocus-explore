# Automated local-study journey

Run `npm run test:journey` to exercise the complete local CSV → analysis → save → reopen → Excel export application journey. The same three cases are discovered by `npm test`; this is not a separate test that the normal suite can omit. No dependency, service, credential, database or production setting is required or changed.

The test mounts the real `App` at Home, chooses **Import local CSV**, supplies a fabricated 1,000-row/30-field file, reviews it and explicitly adds it. It creates a report through Home, opens the analysis tool, selects the imported grouping and breakout, creates a count table on a separate page, reopens the application from the persisted workspace, checks the Excel plan, and invokes the real Excel download action. It captures the generated Blob at the browser download boundary and parses its actual ZIP/XML contents.

Three complete journeys run: normal saving, a denied workspace write during import, and a denied workspace write during analysis creation. Both failures use the real storage writer/session and **Retry saving**, retaining the entire candidate rather than silently reporting success. The tests require the old saved version to remain intact during denial, the candidate to survive retry, no pending save after acknowledgement, and the full report and study to survive remount. They check that controls used are enabled and outside inert dialog backgrounds.

The source generator independently defines all 30,000 string cells. The oracle counts its rows directly, without calling the analytical engine or using a saved result as the numerical reference. Every one of the 350 table values and 350 bases is checked before and after export. Both raw and display labels are literal XLSX text; the synthetic `=1+1` answer must remain an inline string with no formula element. Existing studies, other report drafts and snapshots must remain equal, and no fetch is permitted. Export preflight and download must not change the saved report or original study.

Optional `ECOFOCUS_JOURNEY_ARTIFACTS` writes the generated three XLSX files and synthetic oracle JSON files to a named local test directory. These files contain fabricated data only. A separate Python `zipfile`/ElementTree check can validate ZIP CRCs and recount all workbook cells from those source rows without relying on application export helpers.

## Verification boundaries

This is an automated application integration gate under jsdom, not native-browser acceptance. It simulates only browser facilities: CSV Worker message transport (the real controller/parser runs), File/Blob, dialog geometry/scroll facilities, ResizeObserver, and the final anchor/Object URL handoff. It neither mocks the App, importer, analytical engine, save session, persistence codec nor XLSX exporter. It does not replace a browser Worker/CSP/performance test, an OS chooser/download, fresh browser-process/crash testing, multi-tab atomicity, touch/screen-reader review, live Snowflake verification, native Excel rendering or PDF/PowerPoint visual acceptance. The reopen is an App unmount, cleared save-session memory and remount reading actual persisted bytes in the same test process.

No CI service is provisioned or run by this change. `npm test` includes this gate through normal test discovery; wiring or running a hosted CI job remains an explicit repository action. The original goal 5 is submitted for independent acceptance of the automated local application journey; it is not counted complete here and does not imply all source types or export formats have native end-to-end acceptance. Goal 11 and its browser verification blockers are unchanged. No merge or deployment is included.

An existing import-recovery test exceeded its implicit one-second readiness wait in the first complete suite run while passing alone. Its helper now has an explicit five-second readiness budget and stage/DOM diagnostics. A controlled 1.2-second CSV worker-start delay exercises the same actual App quota/retry test; the pending check now requires the intended imported study rather than any unrelated pending save. All existing source, report, old-save, retry and reopen assertions remain. This does not change the product's worker deadline, certify performance or establish which readiness stage caused the original nondiagnostic failure.
