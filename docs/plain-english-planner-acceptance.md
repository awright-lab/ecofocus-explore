## Complete workflow

Open **Start with a business question** from Analyze or command search. Enter a question, title and study. **Suggest analysis plan** translates supported explicit requests for response counts, response percentages, numeric means or totals. For example:

- `What percentage of [response field] by [comparison field]?`
- `How many responses to [response field]?`
- `Average [number] by [grouping field] for [saved audience]?`
- `Total [number] by [grouping field] for all respondents?`

Use actual field wording, a raw column name or an exact declared concept, omitting brackets. Counts/percentages may omit a comparison; a numeric request must name its grouping. `column [raw name]` explicitly disambiguates a raw column. Supported examples and the rule-based boundary are visible in the product.

The proposal shows the selected study, grouping, measure/comparison, calculation, audience and table output, with a reason for every choice. No query runs. An unstated audience visibly defaults to all respondents. An explicitly requested saved audience must match uniquely and retain valid import provenance; ambiguous names, duplicated identities and an `All` audience-name collision require clarification.

**Use editable plan** fills the existing controls. The user can change fields, metric, audience and output before the separate **Preview analysis** action. The deliverable title remains required. Preview computes from the local study; choosing an exact available cell, authoring the interpretation and explicitly reviewing the resulting pages precede the single report write. Undo, Redo, saving and reopening follow the existing document workflow. Closing preserves adopted choices in this tab's unfinished draft cache; proposals themselves are not persisted. No model/provider configuration, credential, service call or paid dependency is added.

## Refusal and scope

Unknown or ambiguous fields/concepts, unsupported conditions, weights, trends, significance and causal requests do not produce partial plans or guessed filters. Broad business questions such as “Which regions should we investigate for growth?” require an explicit manual analysis choice. Users can continue manually. The grammar does not support arbitrary paraphrases, named answer-value filters, free-form formulas, multiple numeric measures, general linguistic inference or unquoted separator words embedded ambiguously inside field/audience names. Balanced straight or curly double quotes protect whole names containing by/across/for; malformed, escaped and unsupported quote forms require clarification. Unique raw-column wording or manual controls provide a fallback.

Changing the question, relevant metadata or audience invalidates an existing proposal; acceptance repeats translation against current context. The proposal independently snapshots selected fields (including raw sourceColumn mappings, value labels and role metadata) and recorded study/source bindings, rather than relying only on rendered labels. Raw column names are visible in its rationale. Adopted bindings remain attached through preview and page creation; later binding changes withhold cached results and require explicit review of the displayed old/current raw columns before a fresh query. Explicit manual field choices capture current bindings. Changing a mapping with identical field IDs, labels and import event requires a new reviewed proposal. Missing/partial/remote studies, invalid import events, conflicting field identities, stale audiences and studies above 50,000 rows are refused. Final preview and page creation independently revalidate source context through the existing workflow. These are recorded import checks, not immutable content authentication.
