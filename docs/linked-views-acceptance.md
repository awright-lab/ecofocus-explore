# Linked interactive views - original goal30 review candidate

Original goal: select a group in one chart and explore it in related charts, with visible filters and an easy path back. This candidate implements a dedicated, temporary local exploration workspace. It is not independently accepted yet.

## Workflow and boundaries

- Explore rail tool and searchable command open an accessible dialog containing the report's eligible analyses, including analyses on other pages. Choose a complete local study from the shared workspace study registry. Source charts are displayed with accessible group-selection controls in the adjacent result table; direct pointer hit-testing on individual bars is not implemented.
- Selecting a group uses its recorded raw category key, never the potentially duplicate display label or a generic all-filter sentinel. The selected row is checked against a fresh local query before it is used. Contradictory cached category keys, labels, values or bases refuse selection rather than filtering a different population.
- Every eligible related view recalculates locally for the same chained selections. Conditions use AND and intersect each view's existing filter and saved audience, preserving its own valid-response bases. A zero intersection remains empty. The numeric result and sample base are visible in the associated table even when a chart cannot show observations.
- Sticky active-filter chips, Back one selection and Reset linked filters provide a visible return path. Search affects only displayed groups, not the population. Repeated choices are rejected. Close/reload starts a fresh exploration; this temporary state is not saved, exported, published or advertised as crash recovery. Saved source analyses, story evidence and respondent rows are not replaced.
- Missing/replaced study imports, incomplete browser rows, remote/weighted/derived/authored/wave queries and ambiguous identities refuse or are explicitly listed as unavailable. Replacement imports require an explicit new exploration. No services, credentials or provider settings are used.
- Current bounds:50,000 complete local rows,12 eligible views,8 chained selections,100 matching group controls and8 displayed result columns per view. Search reaches other groups. Filtering still applies to every computed cell. Excess view counts fail explicitly rather than silently omitting views. These bounds are implementation limits, not a large-study performance guarantee.
- The grouping/category vocabulary follows the existing imported query engine. This does not implement cross-study harmonization, hosted viewer policies, survey-weighted inference, significance tests, persisted cross-filter state, canvas-wide direct bar brushing, screen-reader certification or touch acceptance.

## Audience-budget correction for independent re-review

Review found that wrapping a valid saved audience inside another AND group exhausted its permitted rule depth or node count. The local query engine now compiles the original audience and temporary linked audience independently and intersects their predicates. It preserves exclusions and unknown-response handling without flattening, relaxing validation, or rewriting saved rules. The executed source context retains both definitions separately; original ordinary queries keep their prior shape.

Temporary intersection results are explicitly rejected by ordinary saved-query replay, durable evidence attachment and formatted report export. Explore itself never places those temporary copies in the report; original report exports remain available. This prevents another workflow from silently dropping the linked scope.

Seven additional regressions cover valid depth6/63-node/64-node definitions, chained selection and Back/Reset, unknown exclusions, invalid source versions, source metadata, original-rule preservation, replay/evidence/export refusal, and both boundary definitions through the dialog.
