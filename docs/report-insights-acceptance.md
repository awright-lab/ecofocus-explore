# Selected reviewed report insights

The existing single-family comparison review can now add complete reviewed plans to a temporary report-level feed. Open **Explore reviewed report insights** from Find a tool, or add a family after running the event-rate review and open the feed directly. Other families can be added through the same explicit assumption review. Closing the panel keeps its plans in this editing session; reloading or leaving the report clears them, with unload protection while queued plans exist. No report, source row, audience definition, result cache or workspace schema is changed.

The queue supports five complete families and20total comparisons from original, complete local-file studies, each with1–50,000rows. It holds copied plans, selected field metadata and SHA-256 digests of the exact reviewed context, rather than complete respondent rows or cached probabilities. Digests detect changes; they do not authenticate a source or its sampling claims. Plan metadata is limited to2MiB, combined selected source bindings to20MiB; these are application budgets, not a guarantee of total browser memory. Unsupported, duplicated or overlapping comparisons are rejected; no family is silently trimmed. Explicitly adding the same reviewed definition replaces its previous queued plan.

Every feed run verifies each recorded context and recounts/tests all selected families through the existing unweighted Fisher review. One Holm step-down adjustment then covers their complete union, including uninterpreted empty/invariant positions retained as p=1. Display filters, research priorities and changing the displayed alpha do not remove tests from that union. Original family thresholds and adjustments remain inspectable. See the primary definitions for [two-sided Fisher testing](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.fisher_exact.html) and [Holm adjustment](https://www.statsmodels.org/stable/generated/statsmodels.stats.multitest.multipletests.html).

This is exploratory selection, often after viewing results; it is not a prespecified confirmatory test or an automatic search of all report charts, studies or waves. Different outcomes are not interchangeable. Rankings use global adjusted-evidence category, explicit question priority, exact absolute percentage-point difference, minimum valid base, combined target/reference missing/excluded share, then selected order. These heuristics do not establish business importance, precision, power, population representation or causation. Validity still depends on the declared independent unweighted sampling assumptions. Weighted, paired, clustered, prepared, partial and remote studies are not silently substituted.

Cards retain study/import identity, outcome/audience, original numerator/denominator in both groups and missing/excluded counts. Inspect original counts opens and focuses the corresponding complete evidence detail, including field IDs, event/exclusion codes and research notes. Source/audience/import/metadata changes revoke the accepted run and require an explicit new review. A private runtime acceptance record checks counts, plan identity and currentness; forged or mutated run objects cannot simply supply a true callback to gain a rank. Changing the selected queue hides the old feed synchronously, before passive cleanup effects run. Canceling or closing stops pending work; late admission after report changes or unmount is rejected. Cryptographic verification failure has an explicit error, without an unchecked fallback.

Validation includes a complete App journey over a synthetic1,000×30study: two reviewed families/three comparisons, priorities, exact cutoffs, unchanged adjustment scope, focused count inspection, modal handoff/focus return, panel reopen, cold reopen and exact preservation of saved report drafts and source data. Queued plans are deliberately absent after cold reopen. Model/hook/component tests cover staleness, cancellation, overlap, density, metadata budgets, mutation, missing outcomes, rank ties and malformed input. Independent Python Fraction hypergeometric enumeration/global Holm and90-digit Decimal logs supply six reference sets/34comparisons, including a20-comparison union and exact alpha boundary. Production Node checks also run a50,000-row synthetic study; this is not native browser performance acceptance.

The React review skill was applied: hooks and ownership are explicit, no external data fetch/dependency was added, native tables and modal focus handling are reused, and the queue is scoped to the report editing session. Full-suite/type/build results, numerical error and backups are recorded in the separate review packet. Native browser layout, screen-reader/touch/fullscreen behavior, live Snowflake, cross-wave comparability, persistence/cloud sharing, exports and native Office/download acceptance are not established by this feature.

Original goal26 remains partial: this delivers a bounded multi-question reviewed feed, while automatic report/chart coverage, validated changes across waves, durable intelligence workflows and native acceptance remain open. No new original goal is counted complete. No publication, merge, deployment, production data, permission, credential, billing or environment security change is included.

Independent review corrections: removing a focused family conditionally moves focus to the persistent review-another action after its button disappears; unfocused removal and a parent retaining the button do not redirect focus. Exact own data-property shapes now reject hidden properties/accessors and serialization hooks before queue signatures, snapshot validation or later serialization. The queue hook validates a plan before cloning it. Five pre-fix runtime probes reproduced the hidden-metadata gap; these are defensive JavaScript-object checks, not evidence of an external exploit through ordinary UI or JSON-loaded data. The separate uncertainty display changes no report-feed calculations.
