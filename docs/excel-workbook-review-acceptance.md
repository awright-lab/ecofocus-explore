# Read-only Excel workbook review

Review before exporting now includes an explicit **Check Excel workbook** action alongside the existing PDF layout and embedded-image checks. It uses the same `buildXlsxWorkbookPlan` function as the existing XLSX writer. No second implementation guesses worksheet contents: sheet names/order, analytical values/bases, context rows, evidence and included narrative text come directly from that shared plan. The writer still constructs fresh worksheets and applies its existing checks when exporting. The plan extraction preserves the complete workbook bytes for four frozen baseline fixtures; it does not change PDF/PPTX generation.

The review checks every cell of the bounded plan, reports sheet dimensions and exact cell addresses, and flags existing text, XML and worksheet limits. Numeric advisories identify values that may exceed Excel's documented stored-number range or15-digit precision; they do not round or rewrite them. See [Microsoft's Excel specifications](https://support.microsoft.com/en-us/excel/excel-specifications-and-limits). The review is not native Excel rendering, a guarantee of workbook interoperability, validation of every version's numeric behavior, source authentication or approval to share. It evaluates cached report context, not live datasets or external service changes.

A worksheet browser renders at most25rows×8columns at once, with navigation and direct row entry. All valid planned values and bases remain reachable, including columns beyond Z. Blank positions are labeled empty rather than zero. Cell snippets explicitly abbreviate long text; selecting a cell opens its complete value/type in a focused read-only inspector with a return-to-cell action. Full text up to32,767UTF-16characters can be displayed; a longer cell is explicitly refused by the inspector and remains unchanged in the report/JSON. Formula-like strings remain literal inline text in this writer, not evaluated formulas. Actual Office interpretation and visual presentation remain unverified.

The plan discloses scope omissions: images, shapes, page backgrounds and canvas layout are not reproduced; standalone text on pages without recorded evidence links is not included. On linked-story pages the existing evidence worksheets and visible authored text are included. Hidden output objects are omitted, while hidden analyses may still be checked as evidence dependencies. The review does not silently add omitted content or repair invalid cells.

Inspection budgets are separate from Excel/export limits:100report pages,100,000planned cells including hidden source analyses,8,388,608JSON input characters and1,000,000visited values. Only the first200issues are displayed, with blocking format issues prioritized; all supported plan cells are still checked and total issue counts remain visible. Over-budget inputs are explicitly refused, not sampled or declared invalid workbooks. Raw respondent datasets and omitted image payloads are not copied or inspected. These caps do not establish total heap/CPU/browser performance or export capacity.

The asynchronous check yields during cell validation, supports cancellation, and refuses changes to the relevant report/export context. This includes labels, query/cached data, evidence, omission inventory and analysis layer order (which determines worksheet order). Cosmetic palette changes do not change the workbook. The same check button persists through cancellation/completion; if an obsolete/removed viewer control owned focus, focus returns conditionally to Check without stealing another control's focus. The inspector handles selection/return and the existing modal owns keyboard shortcuts. Nothing is saved, fetched, downloaded or published by inspection.

Verification includes a100×20analytical matrix from a1,000×30synthetic study, navigation to every4,200analytical worksheet cells (two labels plus each value/base pair per row), literal/long text, numeric/text limits, exact addresses, disclosure, cancellation, stale context and focus. An actual App menu/check/inspect/key/close/cold-reopen journey preserves the original saved report/study and starts no download or fetch. Four actual XLSX artifacts remain byte-identical before/after extraction under a frozen export time; independent ZIP/CRC/XML checks compare every planned cell, name and dimension with the generated workbook. These do not establish native browser/Excel/Office/OS-download acceptance.

Original goal36 remains partial. Native visual/accessibility/Excel/PowerPoint acceptance, broader format-specific checks and other documented export/storage gates remain open. No underlying analytical method, workspace writer/schema, credentials, permissions, production data or security setting was changed. No merge or deployment is included.
