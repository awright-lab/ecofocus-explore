# Numeric profile means after total overflow

The previous online fallback could report approximately -4.99e291 for the finite observations `[-1e308, -1e308, 1, 1e308, 1e308]`. Exact arithmetic over those binary64 input values gives total 1 and mean 0.2. A finite-looking online estimate was not evidence of correctness after intermediate overflow.

Profiles now omit that estimate. When the existing retained-remainder summation provides a finite total, the profile uses total divided by valid observation count, retaining the separate nonzero-underflow guard. After total overflow, only two cases remain available: identical observations have their observed value as the mean; exact opposite pairs have zero mean. Every other overflow mean is explicitly unavailable, with a rescaling explanation. The total-overflow warning remains.

This deliberately refuses some mathematically representable answers, including the reported 0.2 and some exact zeros lacking the pair proof. The existing summation has sticky intermediate overflow, so source order can affect availability. This correction prevents its unsupported fallback from inventing a result; it does not add arbitrary precision or promise order-independent availability. No source values, stored row order, valid counts, missingness, extrema, median or distribution are rewritten. Historical result caches are not recertified or replaced.

The reference fixture uses Python Fraction arithmetic over exact binary64 input values and records exact numerator/denominator and rounded reference bits. Nine reference cases distinguish mathematical answers from the conservative supported-range policy. Regressions cover all 30 distinct permutations of the reported input, maximum finite constants, exact opposite pairs, underflow, exclusions and source preservation. Component workflows inspect both five-row and 5,000-row synthetic studies, save/reopen through the actual workspace codec and verify unchanged workspace bytes and source values. The larger component case runs real preparation/model code through a simulated Worker transport; it does not establish native Worker scheduling or browser performance.

This is a bounded analytical correction, not completion of another original roadmap goal. Native browser/assistive-technology behavior, live Snowflake, Office rendering and OS downloads remain unverified. The subsequent [category alias correction](category-alias-acceptance.md) addresses the separately identified labeled-code merging defect; the numeric profile correction alone does not certify category membership.
