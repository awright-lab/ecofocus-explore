# Inspect where a study is used

In the builder's Data → Study library, **Where used** opens a read-only usage snapshot for the selected current library identifier. Users can inspect dependencies before attempting removal, rather than seeing only the first few references after a failed removal attempt.

The **Current references** view uses the same existing dependency contract as study removal: report analyses, reusable analyses/calculations/layouts, saved audiences, response coding, narrative evidence, preparation history, saved insight plans, new-wave history and legacy snapshots that lack their own study copy. It includes archived reports. The current editor's existing Undo/Redo or running-analysis retention message is displayed separately; individual Undo/Redo revisions are not enumerated. Unreadable saved insight plans appear in a separate **Needs review** view and preserve the existing removal safeguard. Known references are still enumerated in the same report; warning records are not counted as references. Needs review counts report/snapshot safeguard records, not an unknowable number of individual dependencies. A readable source identity retained inside a quarantined plan remains a recorded reference, while any remaining unknown dependencies stay separately guarded.

The **Historical copies** view lists snapshot-owned records with the selected identifier, including report/version metadata and each recorded study import time. These are separate historical copies. Matching identifiers or labels do not prove equal contents or comparable versions, and this view does not calculate source fingerprints. Removing a current library entry does not remove those historical copies.

## Unsaved edits and preservation

Inspection overlays the current draft into a new shallow workspace/report view. It does not call the upsert, normalization, save, deletion or navigation APIs and does not update timestamps. Metadata is copied into frozen strings/records; source response tables are not copied or read. Later edits require **Refresh study usage**. A failed refresh retains the previous same-study snapshot with an explicit notice; missing/ambiguous identities refuse without substituting another study.

Search is literal and case-insensitive over report/item/version/identity text. Each page renders at most 20 records. Empty results are described as no recorded entries in this inspection, not as proof that a study can be deleted. Removal always performs its own current-state checks separately. This tool has no removal or report-navigation action and makes no service request.

The controls and scroll region remain present during search, paging and refresh, so a focused control does not disappear when results shrink. The dialog traps focus, dismisses on Escape and conditionally restores focus without stealing a later deliberate move. Builder keyboard scope protects background report objects from Delete/Backspace while inspecting records.

## Bounds and evidence

Inspection accepts at most 500 report records, 1,000 historical snapshots and 1,000 current library studies, with at most 5,000 returned references or historical copies. Unsupported metadata or excessive lists refuse rather than truncate. Identifiers, titles, timestamps and reference descriptions have explicit string bounds. Existing saved-metadata dependency traversal remains synchronous; this is not a total heap, latency or arbitrary-JavaScript sandbox guarantee.

Model tests cover unsaved-draft projection without timestamp/source mutation, prepared dependencies, owned versus legacy snapshot copies, unknown-plan safeguards, identity/metadata refusal and list limits. Component tests cover bounded paging/search, refresh/error ownership, source identity, keyboard trapping/Escape and owned/outside/blur close focus. The actual App test blocks saving, renames an analysis through its normal canvas control, waits for that exact pending candidate, inspects current references and historical copies, refreshes and tests Delete/Backspace while asserting the saved workspace, pending candidate and write-attempt count remain unchanged. Retry then succeeds and the inspector reopens with the saved edit; the 1,000-row source and historical snapshot stay intact.

Tests use synthetic data and simulated DOM; reopen is same-process. Native browser, assistive technology, touch, fullscreen transitions, real quota/crash/multi-tab and large-workspace timing remain unverified. Remote source metadata can be referenced, but live backend dependencies and external files are not inspected. This is scoped progress toward original storage-management goal 4, not completion of that goal. The prior production-build EPERM is not retried. No publication, merge or deployment is included.
