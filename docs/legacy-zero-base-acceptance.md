# Legacy percentages and averages with unavailable bases

Legacy saved percentages and averages previously bypassed the imported-result denominator check. A recorded 75 with base zero could appear as 75% or an average of 75 beside n=0. Presentation now withholds percentages and averages with zero valid observations; it reports an invalid base as unavailable. The original numeric measurements, bases, series and raw recovery/export JSON are preserved, rather than silently recalculated or rewritten.

An available percentage or average requires an own finite, nonnegative recorded base, integer for unweighted results. Zero means no observations. Positive fractional weighted bases remain supported and are not described as respondent counts; requested but unconfirmed weighting keeps its existing warning. Imported averages still require recorded per-cell measure-base scope. A recorded count/sum zero remains available, and calculated arithmetic retains its separate denominator semantics. This check does not authenticate legacy metadata, infer missing counts or validate survey inference.

The shared rule reaches canvas and thumbnail values, full table browsing, recorded-result explanations, narrative-link eligibility, reconstructed SVG analytical views used by visual exports, XLSX values, native PPTX chart points and JSON cell-status metadata. Donuts require every contributing value to be available, so an unavailable category cannot silently become a complete-looking partition. Unavailable table cells do not carry cached annotation/comparison markers. Base labels and explanations use the same own-base check; invalid or inherited bases no longer masquerade as sample sizes or crash canvas base formatting.

Regression acceptance includes all three percentage/average metrics; observed zero with positive base; invalid, absent and inherited properties; weighted bases; imported-average compatibility; count/sum/calculated compatibility; all three saved input formats; real App edit/save/undo/cold reopen and read-only local snapshot viewing. Each App case retains all rows and fields of an unrelated synthetic 1,000-row, 30-field study, original result values/series and the frozen snapshot. No server request is used.

Inspectable synthetic workbooks, SVG and native-chart XML are generated in a separate local artifact packet. A separate Python ZIP/XML reader checks exact workbook value/base pairs, omitted native chart points, unavailable SVG cells and raw numeric preservation. Native browser, PowerPoint/Excel rendering, PDF raster fidelity, fullscreen, assistive technology and OS downloads remain unverified. ZIP/XML and jsdom evidence do not substitute for those acceptance gates. No publication, merge, deployment or production/security change is part of this correction.
