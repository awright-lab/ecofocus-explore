# New file imports do not replace retained study identities

The mounted Home and Builder file-import paths previously called the generic dataset upsert after a service returned a result. A result reusing an existing study ID could replace its contents even if its answers no longer matched the local duplicate check. Ordinary parsers generate fresh IDs; this is a verified defensive service-result boundary, not evidence of native respondent-data loss.

A shared read-only guard now reserves IDs in the root study library, embedded draft and published study copies, saved report references and preparation-source references. A new file import using any reserved identity is kept in the existing deferred recovery queue and does not invoke the workspace writer. The same guard protects explicit local CSV/separate-copy additions; those already have a retained import review when refusal occurs. It does not alter the generic upsert used by intentional modeling or prepared-copy updates. Repeated identical results also require explicit idempotent recovery rather than being silently treated as an update. Missing or unreadable identity context refuses safely.

Home additionally defers a file result when a different pending-save object needs recovery. It does not supersede that pending workspace. Builder retains its existing owner, replacement-version and pending-save checks. The guard applies to returned service results regardless of local, Netlify or Supabase storage status. It cannot reverse an upload already performed by the configured provider; tests use synthetic mocked service responses, never a live service.

This is a direct-import preservation guard, not all-route collision safety, global concurrency or crash durability. Existing deferred recovery retains its stricter additive checks and may still need explicit source/backup review for conflicting copies. No IDs are automatically regenerated or rebound, no old cache is repaired, and no stored data or historical snapshot is rewritten by the check. The recovery queue is memory-only; keep the original source file.

Verification includes pure reservation checks and actual App/session regressions for changed and unchanged reused IDs, provider statuses, unrelated pending saves, rejected recovery, source preservation and same-process reopen. File chooser/network behavior is simulated. Native browser, server identity assignment, quota policy, simultaneous tabs and process crashes remain unverified. Goal 4 remains partial. The prior production-build EPERM is preserved; this batch makes no build retry, publication, merge, deployment or security changes.
