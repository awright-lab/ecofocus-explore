# Complete recorded table browser — goal15 partial improvement

Large canvas tables now show an explicitly labelled preview of at most50 answer rows by12 result columns. A table is large when either dimension exceeds those limits. Smaller tables retain their existing full canvas presentation. The preview offers **Explore complete table**, which opens a read-only table browser. This limits initial data-cell rendering without deleting or shortening the recorded result.

The browser shows at most25 answers by8 columns per page. Independent answer/column search, first/previous/next/last and validated page jumps reach all recorded cells. Searches match source labels, explicit display overrides and raw IDs with Unicode normalization. Duplicate display labels remain distinct; original positions/IDs are visible. Searches only select displayed cells: recorded values, percentages, denominators, test families and source data are never recalculated.

The viewer shows recorded numeric precision, per-cell bases with correct unweighted/weighted/unconfirmed units, explicit missing/unavailable values, safe recorded annotations/comparisons, and full notes/warnings. It identifies editor-setting mismatch instead of pretending the old result has refreshed. Ambiguous/missing row or column identities withhold the browser's cells and require a rerun; records are not repaired. Replacement result arrays reset searches/page and jump drafts. Clear returns to first pages and discards jump drafts. This is a cached-result viewer, not a fresh query, source authentication or new statistical method.

The modal owns keyboard commands, supports Escape/focus trapping and restores the connected opener. If a replacement result removes that opener, explicit close focuses the surviving table group. Page-boundary controls use guarded, focusable aria-disabled states so they do not drop focus at a boundary. The canvas table group and controls own their keyboard events; genuine body/canvas shortcuts remain available outside them.

Follow-up review hardening makes percentage/average availability require a valid own recorded base, consistent with the displayed base status; inherited numeric properties cannot establish it. This is a defensive in-memory case, not a demonstrated persisted-JSON defect. When a result replacement removes a focused search, pager, jump or scroll control, focus moves to the stable Close button only if that disappearing control held focus. Focus elsewhere stays there. The portal chooses the active fullscreen surface at opening, otherwise the document body, and keeps that container stable until close. Component tests cover placement and simulated fullscreen exit; native fullscreen reachability remains unverified.

Exports continue to use the entire recorded matrix and retain their existing format/layout checks. The browser does not make a dense table fit into a PDF or PowerPoint page; complete XLSX/JSON data remains independent of the chosen display window.
