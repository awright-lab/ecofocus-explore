# Read-only stored-row inspection

The imported-study list now offers **Inspect rows**. It opens a captured, read-only view of a complete local-file study, including prepared copies. Users can browse every accepted row and declared/stored column, search literal stored strings, distinguish empty strings from absent properties, and inspect a cell's complete escaped JSON value without editing the study or report.

The table renders at most 50 rows by 12 columns (600 data cells). Independent row/column paging includes validated page jumps. Field search matches stored keys and field labels. Value search supports contains, exact string, empty string and missing property, with optional case sensitivity. Ordinary textarea entry normalizes CR/CRLF to LF in the browser. For exact control characters and line endings, choose Exact escaped JSON string and paste a JSON string including double quotes. This mode is always case-sensitive and decodes escapes before comparison; CR, LF, CRLF and literal backslash sequences remain distinct. Matching affects this display only, not an analysis filter. Source row positions are file positions, not respondent identifiers.

Capture copies raw own string properties without numeric coercion, recoding, case-insensitive key substitution or value-label replacement. Metadata-only keys remain visible as absent; extra raw keys are retained. A final source comparison rejects changes during capture. The accepted snapshot is frozen and remains labelled as a snapshot until an explicit successful refresh. Cancelled or failed refresh keeps the previous snapshot; no alternate, remote or preview-only study is substituted.

## Bounds and remaining limitations

- Complete local-file studies only: at most 50,000 rows, 200 metadata fields/distinct raw keys, 500,000 stored properties and 8 Mi UTF-16 source characters. Per-cell limit is 65,536 code units. Escaped exact search allows up to 393,218 encoded code units (the worst-case JSON representation of one maximum-size cell), then enforces the decoded cell limit. The readable preview is labelled as browser-normalized; only the escaped JSON representation claims reversible exactness. Oversized or unsupported input refuses intact; nothing is truncated from the accepted snapshot.
- Capture and value search yield in 250-row chunks, expose progress and support cancellation. Their 30-second deadline depends on the event loop; final source verification is synchronous. This is not a Web Worker or a proven browser responsiveness/memory guarantee.
- Rows must contain own enumerable string-valued data properties. Sparse arrays, accessors, hidden/symbol properties and unsupported prototypes are refused. This validation is not a sandbox for arbitrary JavaScript or hostile Proxies.
- Snapshot freshness is explicit. Later in-place source mutations do not silently update the view; Refresh is required. A changed dataset object can show a conservative context-change notice.
- Focus stays within the dialog, restores conditionally on close, and transfers to a stable heading if a focused cell disappears. Keyboard guards prevent dialog Delete/Backspace from deleting background report content. Native screen-reader, touch, fullscreen transitions and browser-matrix acceptance remain unverified.
- Raw values can contain sensitive respondent text. Inspection issues no network request, export or persistence write. Existing storage and backup privacy characteristics are unchanged.
- This is scoped progress on original goal 15, not completion of background import/calculation performance or the entire original goal.

## Verification

Synthetic model coverage includes exact keys, reserved names, missing/empty strings, sparse/accessor refusal, capture currentness, cancellation and bounds. A line-ending regression imports quoted CSV containing CR, LF, CRLF, literal backslashes, quotes and tabs through the real parser, then verifies escaped display/search and source preservation. Additional cases cover unpaired UTF-16 surrogates, invalid JSON/non-string values and maximum-size escaped cells. A 50,000-row/three-column fixture checks all 150,000 stored cells and all 1,000 row pages. Dialog tests cover bounded DOM, paging, exact/multiline searches, cancellation, snapshot refresh and conditional focus. The actual App workflow covers 1,000 rows by 30 fields, final-row/final-field inspection, background keyboard protection and exact workspace/raw-source preservation through unmount/reopen. Same-process reopen and simulated DOM are not native process-restart or OS-download acceptance.

See the external candidate manifest and verification logs for exact source hashes, test counts and archive integrity. The production build is not retried after the earlier EPERM; native browser acceptance remains open. No merge or deployment is performed.
