# Move one report object to another page

A selected unlocked analysis or element now has a **Move to page** action in the canvas toolbar. The review lists destination pages by their visible page order and unique IDs, including ordinals when titles repeat. It keeps the object's ID, query/result, content, source links, box coordinates, size and layer value. Only the two page object arrays change. Related objects remain on their current pages; this is not a multi-object/group move or a copy. The existing document command provides one Undo entry and uses the existing save/recovery path. The destination opens with the moved object selected.

Overlap checks include hidden destination objects and the shared chart-frame minimums. Possible overlap, off-page placement or geometry that cannot be checked requires an explicit placement review; otherwise moving needs no extra acknowledgement. The operation does not find a new location, resize boxes, reorder layer values, measure text/effects, or certify exports. Equal-layer objects can paint in destination-array order. Unsupported source geometry or ambiguous page/object IDs refuse without normalizing or dropping the existing objects.

The review is bound to the current immutable report and editor context. Ordinary edits, report/page/view changes and replacements refuse stale acceptance; destination layout/order changes also invalidate the lightweight review key. The move rechecks these conditions at command time. This is not a cryptographic snapshot of every respondent row or a sandbox for arbitrary JavaScript mutation. Source objects and their nested data are retained rather than reconstructed. Existing evidence references can resolve by the unchanged tile ID across pages, while historical recorded page captions remain unchanged.

The modal uses the existing focus trap, Escape and background keyboard guards. It portals into a captured fullscreen surface when present. Closing/moving returns focus to a connected move trigger, or the connected original control, only while focus ownership permits it. New outside focus and deliberate blur revoke restoration. If a focused placement checkbox disappears during invalidation, a stable Close control receives focus without stealing unrelated focus.

Synthetic verification covers pure transfer and source preservation, hidden/unknown/off-page geometry, stale context/destination consent, duplicate/missing identities, sparse arrays, cross-page evidence, labels/order, focus/no-focus-theft, fullscreen portal ancestry and no duplicate insertion. The actual App journey uses a 1,000-row/30-field study with historical published data, moves chart and text, checks Undo/Redo and locks, simulates save refusal and Retry, and reopens the saved state in the same process while comparing the complete expected draft, study and published history.

Native browser pointer/focus/fullscreen behavior, screen readers/touch, visual layout and export/Office/download acceptance remain open. Tests simulate localStorage refusal; real quota, process crashes, multi-tab and delayed asynchronous writers are not established. The earlier production-build EPERM is not retried. Goals 16, 33 and the broader story workflow remain partial; no original-goal completion is claimed.

Lifecycle correction: moving from a previously published report marks the editable report **draft**, matching existing page/content edits. The last-published metadata and immutable snapshots are retained. Undo can restore the prior published report; Redo returns to the moved draft. Actual App regressions check JSON/Excel status labels through that sequence and after save/reopen. A separate export-consumer check verifies PDF/PPTX/XLSX draft/published filename suffixes; raster output and downloads are mocked there, so it does not establish visual or OS-download acceptance.
