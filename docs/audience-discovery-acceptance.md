# Audience discovery: original goal 23 candidate

Original goal: explore potential customer segments with stability checks and warnings for groups that are too small or unreliable.

## Supported workflow

Find a tool → Analyze → Discover audience segments. Choose a complete original local-file study, a business question, distinct respondent ID and single-choice outcome fields, and one or two categorical segment fields. Explicitly choose event and excluded codes, review the independent unweighted design, then run discovery. Inspect event counts, known nonmember counts, percentage-point differences and split behavior; select a segment and explicitly add its source-bound rules to the report audience library. The existing Audiences control can edit or reuse the resulting definition.

Limits: 1–50,000 rows, complete fields/rows, selected projected inputs ≤20 MiB, categorical raw codes ≤128 characters, up to 20 observed categories per segment field, up to 200 observed outcome codes, and at most 440 overlapping candidates. Respondent IDs must be unique and nonblank across the entire study, including rows with excluded or missing outcomes. Trimmed IDs are used without numeric coercion. Original import and exact selected field metadata bind the plan; source/plan changes revoke results and approval. No remote or prepared study is substituted.

## Descriptive methods and safeguards

- The fixed `EcoFocus-discovery-v1` noncryptographic ID hash orders all respondents, with code-point ID order breaking hash ties. The first ceil(n/2) rows in that order are discovery; the rest are validation. This is balanced and row-order invariant, but **does not establish random sampling, independence or representativeness**.
- Candidates include each observed single-field category and, with two fields, their Cartesian conjunctions. Rules use the existing audience compiler's category-code normalization. Overlapping audiences must not be summed. Candidate generation inspects source categories; outcome-based ranking uses only discovery counts, never validation effects or flags.
- Event rates use valid nonblank, non-excluded outcomes. Each segment is compared with known nonmembers, not the overall population containing the same members. Unknown membership is excluded from both bases and counted separately. Conjunctions use the existing three-valued audience semantics: any false rule means a known nonmember even if another rule is unknown.
- Ranking first separates candidates with at least 15 valid members and known nonmembers in discovery, then sorts absolute discovery percentage-point differences; ties use stable candidate keys. All candidates remain inspectable, including sparse and empty cross-combinations.
- “Pattern repeated in split” requires ≥30 valid members and nonmembers overall and ≥15 of each in both halves; discovery difference magnitude ≥10 pp; same validation direction; validation magnitude ≥half discovery; and split effects within 15 pp. These are disclosed **exploratory heuristics**, not significance tests, validated reliability estimates or business cutoffs. Small, unavailable and changed/weak patterns have distinct warnings. No p-values, confidence intervals, causal or population claims are produced.
- Thresholds and ranking compare count-derived rational differences with exact BigInt cross-products; displayed floating-point differences do not determine the label. This preserves the inclusive 10 pp, 15 pp gap and half-retention boundaries, including negative directions, without epsilon widening. Denominator products can exceed Number's safe-integer range even within the 50,000-row limit. Independent review found and prompted this correction; the original floating-point boundary classifier was not acceptable.
- The calculation uses an immutable projected snapshot, yields in batches, supports cancellation, and rechecks exact current source/plan before accepting results. Selected inputs are bounded before calculations. Main-thread projection and candidate construction are still bounded synchronous work; this does not complete the general background-processing goal.
- Saving requires a separate warning acknowledgement and valid name. Only ordinary audience rules and original study binding are retained. Matching respondents with missing/excluded outcomes remain members of the saved audience. Results and reliability labels are temporary, not saved as certified evidence. Current audience-library validation runs inside the functional report command, protecting concurrent additions and the 100-audience limit. Existing report pages and source rows are not replaced.
- Adding to the report is explicitly distinguished from durable saving. The builder's existing save status and pending-recovery flow remain authoritative. No new storage format or recovery activation is introduced. Temporary plans, results and name drafts get Close/Escape/unload protection; explicit discard does not remove an already-added audience.

## Verification and acceptance gates

The initial complete code passed 38 focused tests (30 model, 8 component), the full 2,284-test suite with two existing skips, TypeScript and production build. Tests include an independent respondent-level membership/count oracle using the normal audience compiler; source preservation; ID/order invariance; validation-outcome changes leaving rank/discovery counts unchanged; missing/excluded/unknown accounting; code normalization and prototype-like names; stale bindings; cancellation; library-command rejection/current limits; and 50,000 rows × 440 candidates.

Additional actual-App save-failure/retry/cold-reopen verification is recorded in the private review packet with its final result. Test counts here describe the initial run, not an unverified later run.

**Native browser acceptance remains open.** The desktop disconnected during the first attempt. After reconnection, source files were preserved and byte-verified. New browser tabs could not attach; an existing clean tab was readable but the loopback fixture timed out. A read-only health check returned a Windows socket access-permission error for 127.0.0.1:5201. No security setting was changed or denied socket retried. The isolated 1,000-row × 30-field importer/App/writer fixture is preserved for later permitted acceptance.

Independent original-goal review is required before calling goal 23 complete. Weighted, clustered/repeated, remote, prepared, continuous-outcome, unsupervised-clustering, model-prediction, fairness, inference, export and persistent-discovery-result workflows are outside this candidate. No publication, merge or deployment is part of this verification.
