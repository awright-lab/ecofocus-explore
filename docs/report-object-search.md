# Jump to charts and written text across a report

The Pages search now offers direct object matches across collapsed and inactive pages. Search covers page titles/numbers, analysis titles and names, recorded imported source-field labels, element names and authored text. Each quick result names its page, object type and visible/hidden/locked status; text matches include a short excerpt when its case-folded positions can be represented faithfully. Clicking uses the existing page/object selection actions and selection cue. It does not edit the object, unhide/unlock it, zoom independently, write data or contact a service.

The quick list shows the first twenty matches in page/layer order and reports the complete match count. The filtered page tree remains available for other matches. Escape clears a nonempty query while preserving IME composition. Search recalculates against current data rather than memoizing mutable page references, and activation rechecks that the target still matches and has unambiguous IDs within its page. Duplicate names and opaque Unicode IDs are supported without constructing DOM selectors from IDs.

The search model does not scan respondent rows, recorded result cells, image content, evidence JSON or hidden technical metadata. Existing page previews still render their cached content normally. Authored-text matching is limited to 2,097,152 UTF-16 code units across the report. Above that threshold it explicitly reports complete names-only results, rather than sampling written text and pretending the search was complete. Queries are limited to two hundred input code units. This is literal case-insensitive lookup, not semantic or natural-language research discovery.

Quick-result controls have a canvas-shortcut ownership scope. If a focused result disappears, focus returns to the search field only when the removed control owned focus and the user has not deliberately moved it elsewhere; hidden/inert panels are excluded. Otherwise focus remains on the current control. Existing page management and full object actions remain unchanged.

Regression coverage includes model matching, capped results/full counts, text budgets, no result/image reads, same-reference updates, stale/ambiguous activation, Unicode IDs, component focus ownership, hidden/locked navigation and IME behavior. An actual App workflow selects text on a different page, checks Delete/Backspace cannot delete it while the result button owns focus, and verifies source/report/snapshot preservation through same-process reopen.

Native keyboard/screen-reader/touch, scrolling, layout and browser-matrix acceptance remain unverified. No production build is attempted after the earlier EPERM. This supports navigation and accessible authoring but does not close original goal 16. The proposal remains in a separate source copy while the main index is obsolete. Existing accepted candidates/backups are preserved; nothing is applied, staged, published, merged or deployed.

## Duplicate-name accessible results

Each quick-result accessible name includes its ordinal in the matching-object list and the complete match count. Its visible written-text excerpt, when present, has a unique per-panel ID referenced by the button through aria-describedby. Same-page objects with identical names, types and status therefore have distinct focused-button names and associated contextual descriptions. Name-only matches omit aria-describedby instead of pointing at an absent excerpt. A component regression creates two same-name text objects on the same page, checks distinct ordinals and excerpt associations, navigates to each exact ID and preserves the original report. These DOM semantics are verified in jsdom; actual screen-reader announcements remain native acceptance work.
