# Fresh imported analysis in a background worker

The Create analysis dialog offers **Calculation mode** for complete local-file studies with 5,000–50,000 rows and at most 200 fields. The default remains **This tab (existing calculation)**. Background mode builds a fresh analysis; it never promotes a temporary preview into a report.

Selected columns are copied in yielding 250-row batches. Progress describes preparation and calculation. The persistent Cancel calculation button aborts acceptance, detaches callbacks and requests worker termination; it keeps the dialog setup and existing report. The setup controls are disabled while creation is pending. A synchronous request guard prevents duplicate same-batch activation. Worker errors leave an explicit choice to retry or use the existing this-tab path; there is no silent fallback or sampling.

The worker runs the existing imported-study engine with the original study and field identities, labels, source reference and import timestamp. It supports unweighted count, percent selected, column percent, average and sum. Physical measure/breakout/filter roles remain distinct from a synthetic overall-grouping field, even if a real field uses the reserved grouping ID. Only selected source values enter the job; unrelated respondent columns are not copied into its request.

The job refuses more than four selected fields, 5,000 result cells, 2 MiB selected metadata, 20 MiB selected values/expanded row keys, or a 4 MiB result. These are conservative refusal limits, not estimates of total heap usage. Neither source rows nor historical caches are rewritten. Sources, selected metadata and selected values are rechecked before accepting the result and again in the deferred document update. Unsupported remote/live references, missing complete rows, saved-audience configurations and source/setup drift fail without inserting a result.

Preparation and calculation each have a separate 30-second watchdog, so the combined elapsed time can approach 60 seconds plus scheduling. Timers and cancellation cannot interrupt a blocked main thread. Final verification and message serialization still do some synchronous work. Failed worker termination cannot establish an operating-system kill guarantee; detached callbacks still refuse late results.

Verification uses synthetic data only: full-engine equality across five metrics, case-insensitive source columns, reserved-ID role collisions, 50,000-row precision, cancellation, unavailable/malformed workers, stale source/ref/metadata, same-batch activation, keyboard-focus retention, and the actual builder command followed by existing workspace save/reopen normalization. The tests use controlled worker doubles and same-process DOM/storage, not native browser workers or real quota/crash/multi-tab recovery. Production bundling, CSP restrictions, browser responsiveness, assistive technology, OS downloads, Office rendering and live Snowflake are unverified. Goal 15 remains partial.
