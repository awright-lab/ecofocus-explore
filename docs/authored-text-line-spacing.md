# Authored text line spacing in exports

SVG/PDF reconstruction now uses the selected text line height instead of hard-coded ordinary/linked ratios. Capacity follows the authored height, padding and complete line boxes; a taller box can hold more than eight lines. Overflow is still refused rather than truncated. A scale-relative machine-precision tolerance prevents decimal line-box boundaries from falsely rejecting a fitting line; it is not a pixel-sized allowance. For ratios below1, capacity conservatively reserves at least one font-size line box per line while retaining the authored baseline advance. This is a character-count wrapping estimate, not browser glyph measurement.

Editable PowerPoint paragraphs now record absolute authored line spacing using the existing writer's canvas-to-point scale. Missing legacy lineHeight retains the previous SVG advance and unspecified native paragraph properties; no stored style is rewritten. Positive spacing that cannot be represented as a nonzero DrawingML point value falls back to the slide image through the existing eligibility policy; invalid SVG text styles still block export. Point spacing rounds to the nearest hundredth of a point. The existing native minimum font size remains, so baseline serialization is not complete font/glyph fidelity.

[Microsoft documents point-spacing units](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.spacingpoints?view=openxml-3.0.1). The [official OpenXML SDK validator](https://github.com/dotnet/Open-XML-SDK/blob/main/generated/DocumentFormat.OpenXml/DocumentFormat.OpenXml.Generator/DocumentFormat.OpenXml.Generator.OpenXmlGenerator/schemas_openxmlformats_org_drawingml_2006_main.g.cs#L27825) constrains spcPts to0..158400; positive advances rounding to zero are not silently collapsed.
