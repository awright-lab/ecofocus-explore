# Retain complete SAV cases with missing values

The SAV reader already validated and materialized physical cases, but the shared dataset builder removed any row whose cells were all empty. A five-case synthetic file with leading, middle and trailing system-missing cases therefore became a two-row study. An entirely missing file became metadata-only and could unnecessarily enter server fallback.

The builder now retains every case returned by the SAV reader. CSV/XLSX blank-row policies are unchanged. This does not manufacture rows from header counts or replace unreadable data. Existing truncation checks, explicit budgets, unsupported compression behavior, missing-value decoding, analytical exclusions, storage schemas and writers are unchanged.

Physical case counts and valid analysis bases remain distinct. In the five-case example, the numeric profile reports five rows, two valid values and three blanks; the mean stays15 with valid n=2 and sum30 with valid n=2. An entirely missing study retains its physical rows but still cannot execute a numeric summary without valid values. Real zero observations remain valid unless the file explicitly declares zero as its global missing marker. No new overall-count query mode is added.

[GNU PSPP's developer guide](https://www.gnu.org/software/pspp/pspp-dev/pspp-dev.html) describes system files as cases plus dictionary information and specifies system-missing as a stored value. Retaining complete case boundaries is our import-preservation rule; whether a value contributes to a calculation remains a separate analysis decision.

Verification covers uncompressed and standard bytecode-compressed files; declared and unknown case counts; numeric system-missing opcodes, raw markers and an explicit zero marker; space-only string values; fully missing files; genuine zeros; explicit physical-row budgets; and bounded previews. Independent Python struct decoding of the actual old fixture proves five cases at positions0–4, fully missing0/2/4, two valid measurements10/20, exact mean15. The actual prior importer output is frozen with source bytes and hash.

Old stored studies, cached results and snapshots are preserved exactly. The importer cannot reconstruct omitted historical cases without the original source. Explicit reimport creates a separate study. Tests retain the old two-row version, add the corrected five-row version separately, and round-trip1,000cases through compact saves and snapshots. Actual Home/jsdom tests import1,000cases, preserve old reports/studies/snapshots, retain all rows during a simulated quota failure, retry successfully and cold reopen exact data. Parsing previews up to50rows; existing workspace compaction stores25preview rows independently of all1,000respondent rows. Actual handler tests inspect raw upload and ordered row-write arguments through mocked storage; no live database or service is tested.

Scope remains the currently supported classic little-endian SAV paths. This does not implement ZLIB, other float/byte orders, per-variable user-missing rules, default memory bounds or background SAV parsing. Native browser/SPSS/Office/downloads and live backend acceptance remain unverified; denied operations were not retried. No loader migration, production data, credentials, permissions, billing, publication or security-setting change is included.
