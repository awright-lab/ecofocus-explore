# Preserve genuine zeros when numbers are below range

Nonzero decimal text can round completely to binary64 zero. The imported numeric parser now treats that range failure as invalid numeric input, consistently with overflow. Raw source text stays intact; it is not converted to zero or deleted. Fresh numeric summaries/profiles exclude it from valid-observation bases. The later [category alias correction](category-alias-acceptance.md) also protects labeled under-range codes from merging into zero, while retaining exact decimal aliases. This numeric-parser correction alone did not establish that categorical behavior. Raw rows remain intact, and numeric audiences treat an invalid range value as unknown rather than including it in an observed-zero segment.

True zero coefficients remain valid, including signed zero, supported currency/percentage notation and scientific notation with a large exponent. Representable subnormal values remain supported. This correction preserves the existing binary64 arithmetic model; it does not add arbitrary precision or certify every rounding operation. The conversion behavior follows [ECMAScript Number conversion](https://tc39.es/ecma262/multipage/abstract-operations.html#sec-tonumber-applied-to-the-string-type); the unavailable-value policy is this application's explicit choice.

A fresh average whose nonzero finite total divided by its valid base rounds to zero now fails explicitly with a rescaling explanation, before a result can replace the prior analysis. A representable total remains available as a sum. Numeric profiles mark such a mean, or an underflowed midpoint median, unavailable with warnings while retaining valid counts, extrema, totals, distributions and raw rows. Genuine cancellation to zero remains available.

The subsequent [profile overflow correction](profile-overflow-acceptance.md) supersedes the initial zero-only fallback guard: every unproved online mean after total overflow is now unavailable, even when the true mean would be representable. Identical observations and exact opposite pairs retain their provable means. This conservative policy can require rescaling even for a genuinely zero mean without that proof. The reviewed summation implementation and total-overflow warning remain unchanged.

Existing cached results are preserved on load. The user must explicitly preview and apply a fresh execution to replace them; Undo retains the historical result. No unknown historical source is inferred and no old result is retroactively certified. A failed fresh execution keeps the old analysis and all studies.

An independent Python reference uses exact Decimal source-zero classification and binary64 conversion for23vectors, plus an exact Fraction proof that half the smallest positive binary64 value is nonzero even when its conversion is zero. See the [Python decimal documentation](https://docs.python.org/3/library/decimal.html). Regression coverage includes both signs, long decimal coefficients, true-zero exponents, subnormals, categorical codes, numeric audiences, grouped/overall means and sums, profiles, overflow fallback, original data preservation and real App refresh/error/save/Undo/Redo/cold reopen. The App fixture retains every field of a synthetic1,000x30study while correcting North's mean to4 with499valid observations and South's mean6 with500; receipt coverage records one invalid numeric value. A second case refuses an unrepresentable mean and retains the old result.

These tests use local execution, jsdom and synthetic data. They do not establish live Snowflake correctness, native browser accessibility/performance, native Office handling of subnormal values, source authentication or survey inference. No new original goal is claimed complete. Publication, merge, deployment and environment security changes are outside this correction.
