# Stored-value number checks

The Stored rows inspector can find blank/whitespace strings, values accepted by the existing imported-data number parser, and nonblank strings rejected by that parser. It searches a frozen, complete local-study snapshot and shows original row positions and reversible escaped values. Refresh explicitly to capture later changes; refreshing resets inspection criteria.

The checks use the exact selected stored key. Missing properties, empty strings and whitespace-only strings remain distinguishable. Both numeric modes exclude missing and blank values. Decimal points, comma thousands, optional dollar prefixes and percent suffixes follow the shared parser; percent notation is parsed as its written numeric magnitude, without dividing by 100. Nonzero values underflowing to zero and nonfinite numbers are rejected. Stored codes such as 999 are not treated as missing unless another analysis rule does so. No values, analytical filters, reports or saved workspaces are changed.

Text and case choices are retained when switching modes but ignored by format checks. The text control remains focusable and read-only; the unavailable case checkbox is disabled, with a conditional focus handoff to the mode selector when it owned focus. Applied criteria do not display ignored text or case settings.

This is a stored-format review, not a full analytical exclusion audit. It does not infer field meaning, study-specific missing codes, valid weights or survey eligibility. Analytical field lookup can resolve case-insensitive aliases; this inspector deliberately uses exact keys. Existing complete-local snapshot limits, chunked cancellation and synchronous final verification remain in place. Native browser, assistive technology, memory/performance and export acceptance are unverified.

Verification: model partition tests compare numeric/blank/invalid counts to the existing numeric profile; prototype-like own keys, ignored long text and cancellation are covered. Component tests cover frozen values, explicit refresh, retained choices and focus ownership. An actual App test imports synthetic 1,000-row/30-field CSV data, checks 400 numeric, 400 rejected and 200 blank stored Spend values, guards Delete/Backspace, compares complete saved study/report/history and raw storage bytes, and reopens in the same process. No real respondent data or network requests are used. Independent review is pending.
