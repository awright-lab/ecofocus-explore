# Explicit overall grouping without field-ID collisions

An imported field may legitimately have the ID `__ecofocus_all_respondents__` in restored metadata. Previously the authoring controls inferred overall grouping from that string, mixed the real field and virtual option in one selection list, and refused valid queries. Overall summaries could also conflict with a real measure, breakout or filter carrying that ID. This was a refusal/choice-identity defect; no ordinary-flow wrong-count or data-loss claim is made.

Guided creation and the inspector now track the explicit overall choice separately from the selected physical field ID. A deterministic DOM-only option is disjoint from every current field ID and any retained missing real selection. The historical virtual field ID and saved `groupingScope: "all_respondents"` contract stay unchanged. The option token is not saved in queries, field metadata or respondent rows. A missing real field remains unavailable instead of silently becoming a virtual summary. Switching studies clears the virtual choice as part of the existing selection reset.

Execution permits the reserved string as an ordinary grouping only when it resolves to one registered physical field with the same nonempty source column. A virtual grouping still requires explicit numeric scope. For explicit overall scope, synthetic grouping is not a physical field, so sharing its historical ID with a real measure or breakout is no longer treated as selecting the same physical field twice. Actual conflicting physical roles retain their existing checks. Background preview deduplication likewise keeps the virtual role separate from physical fields, while continuing to reuse genuinely shared physical fields.

Verification includes five original-code failures, collision-free choice tests, direct ordinary/overall calculations, retained missing IDs, inspector load/update, and real background projection for grouping, measure, breakout and filter roles. An actual React App workflow uses 1,000 synthetic rows: a restored real grouping opens as a real field; an explicit overall mean split by that field saves and reopens with original IDs, source rows and earlier snapshot unchanged. Its initial content comparison permits only the builder's existing report-record `updatedAt` autosave timestamp. No historical analysis is recalculated or rewritten on load.

This is local imported-query compatibility work. It does not enable remote overall summaries, validate live Snowflake or establish native browser/Worker/CSP/accessibility/Office behavior. No storage protocol, schema version, parser, source row, percentage calculation or CSV-focus behavior changes. Existing publication, deployment and security boundaries remain in force; this batch does not complete a whole roadmap goal.
