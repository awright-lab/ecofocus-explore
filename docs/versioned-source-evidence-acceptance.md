# Original goal14: versioned local result explanations

Candidate, not independently accepted. The pre-existing Explain a result panel already exposes recorded question/source, filtering, weighting, cell-specific bases, unavailable cells and separately retained exact unweighted percentage/mean inputs. This batch adds the missing **opt-in versioned execution** path; it does not relabel historical results as source-verified.

## Workflow and scope

Find a tool → Analyze → Explain a number from source. The current selected analysis is offered initially. Review a fresh calculation and any cell's source evidence before explicitly applying the new result. The normal report command, Undo/Redo, save status and recovery remain authoritative. A successful document update is not reported as a durable save.

Only complete original local imports of1–50,000 rows, selected serialized inputs≤20 MiB, and prospective result≤5,000 cells are supported. Result-integrity payloads are limited to4 MiB. The conservative prospective-cell guard uses unfiltered observed/declared source categories before materializing a dense result; a filter does not bypass that budget. Weighted, remote, prepared, calculated/authored, wave and temporary linked-intersection results are not replaced with a raw unweighted calculation. Unapplied query edits must be resolved first. No extra backend request is made.

The source projection includes every row for the actual grouping, numeric measure, breakout, filter and recorded-audience fields, their metadata, original import identity, row/field counts, source reference and executed query. Canonical JSON preserves string values, Unicode escapes and stable object-key order. SHA256 is computed using WebCrypto. **This is an analysis-input content identifier, not a whole-file hash, an archived raw-data copy, external source authentication, or proof that the current source still matches an earlier run.** Unrelated columns are not hashed. Identical aggregates from changed inputs receive different versions. A previously valid receipt is compared with the fresh version; unknown legacy versions are never reconstructed.

Independent review corrected the projection to use the analytical engine's exact-key-first, case-insensitive fallback lookup for every selected field, including audience/filter fields. Receipt identity and original field count now come from the parsed frozen source serialization; non-row study metadata and prior result are cloned before hashing can yield. New receipts and input projections use method revision2. Earlier revision1 receipts are preserved but their provenance assertions are withheld: the old integrity seal alone cannot rule out the known projection/count defects. An explicit corrected refresh can replace them reversibly. The explanation separately displays the recorded audience name and predicate from the result snapshot, regardless of the current audience library.

The fresh calculation uses the same frozen projection that was hashed, not mutable source rows after yielding. Exact current source/query/result ownership is rechecked before accepting a preview and again before applying it. Normal source data, layout, styles and concurrent unrelated report edits are retained. Projection and calculation remain bounded main-thread work; cancellation is checked around asynchronous digest stages, not inside every synchronous row loop. This does not complete the general background-processing goal.

## Evidence receipt and presentation

Optional `localExecution` metadata records import identity, execution timestamp, projected-field scope, source SHA256, exact disjoint exclusion counts and a separate SHA256 seal over the recorded result and receipt. No source rows are duplicated into the receipt. Seal payload includes query/source context, table/series/columns, weighting, metric and retained pre-rounding inputs; cosmetic outer chart type is excluded. Optional receipts survive normal workspace encoding/normalization. Remote responses containing a local receipt are rejected.

Before displaying a receipt's version, execution time or exclusion facts, the existing explanation panel asynchronously verifies its shape and integrity against an immutable snapshot and current signature. Modified values, bases, query, metadata, exact inputs, source digest, timestamp or coverage invalidate the receipt. Unsupported crypto or malformed evidence withholds new assertions while preserving the original result/raw metadata. **The integrity seal is not an authenticated signature**: a party capable of replacing data and recomputing hashes can create a new internally consistent record.

The query engine exposes a read-only execution-coverage callback: source rows → audience false/unknown → filter exclusions → missing grouping answers → invalid numeric values → included rows. These categories are disjoint and sum to the source row count. They describe the whole query, not each selected cell. Blank breakout values remain their own column. Cell numerator/denominator/valid-n facts continue to use existing compatible recorded calculations and cell bases; numeric sums/counts explicitly have no divisor. Zero observations remain unavailable, not an observed zero estimate. No survey weighting or inference is certified.
