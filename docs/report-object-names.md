# Names that help find report objects

The selected chart's Style inspector now offers **Analysis name**, while the existing element **Layer name** field uses the same staged editor. A rename changes only the object's name through the existing update command. It does not edit IDs, source data, query/results, layout, styles or the separate chart title. The existing empty-title fallback can display an analysis name, so the helper explains that an empty title may display the renamed value. Locked elements retain their prior ability to change organizational names; renaming does not unlock or move them.

When a chart's internal name differs from its displayed title, the page tree and quick search show **Analysis name: …**. Those visible names are also associated with focused selection/search buttons through accessible descriptions. Existing title, ordinal, page and status announcements remain intact. Duplicate names are allowed and do not change identity or selection routing. Search still uses the existing recorded names/source labels/text rules, not respondent rows.

## Applying and canceling

Typing is staged instead of generating a document edit for every keystroke. Enter or moving focus outside the composite name controls applies one rename. Moving from the input to Cancel does not apply it. Escape or Cancel retains the current name; a focused Cancel returns focus to the input without stealing unrelated focus. Whitespace at the ends is trimmed on an actual applied rename; trimming to the existing value is a no-op. There is no optimistic browser-save acknowledgement. Undo and existing failed-save/retry behavior remain authoritative.

A primary pointer press on Cancel holds a possible null-`relatedTarget` blur without applying or discarding the draft; older mouse events have the same fallback. Only completed click activation or keyboard Cancel discards it. Pointer cancellation or release outside retains the typing and its browser-leave protection. If the user instead moves focus elsewhere, ordinary blur application keeps that edit and permanently revokes the old pointer's focus-restoration permission; a later outside blur does not restore it. New typing, keyboard interaction, an outside press or leaving the window also ends the held gesture. A displaced owned input is conditionally refocused only while that ownership remains current. Non-primary presses do not cancel. During IME composition the disabled Cancel only prevents focus displacement; it does not discard or prematurely apply the composing text. Native gesture/capture/default-click behavior is still unverified.

New names must be nonempty, single-line, valid Unicode and at most 200 Unicode code points. Unsupported values reset to the current name and show an associated error rather than writing an empty/truncated label. Existing long, unusual or multiline names are left intact on load or focus/blur; they are not silently normalized. If the actual name changes while a local edit is underway, the current name wins and the stale edit is refused. Replacement selections reset the local editor by the existing object-identity key.

IME composition protects Enter/Escape from premature actions and defers outside-blur application until composition ends. While composing, cancellation/application waits for text composition to finish. Callback exceptions report an unconfirmed change rather than claiming that a possibly applied rename was undone. Current rendered props determine the field's eventual value.

Unapplied edits have a visible status and request a beforeunload warning. They remain transient component state: ordinary focus-changing navigation commits them, but external programmatic unmount/selection replacement before blur, process termination or a browser suppressing its warning can discard uncommitted typing. This batch does not add a recovery journal, route-interception protocol or durable checkpoint for name drafts. Native IME, browser navigation and browser-warning behavior remain unverified.

## Verification and remaining scope

Model and integrated component cases cover Unicode limits, invalid names, no-op/duplicate commits, cancel focus, stale external names, legacy preservation, identity replacement, composition and applied/unapplied callback failures. Tree checks associate distinct internal names with selection/search descriptions. An actual App journey uses a synthetic 1,000-row/30-field study, chart, locked text object and historical snapshot. It checks staging, Enter, Undo/Redo, cancellation, shortcut ownership, tree/search names, simulated failed save, Retry and same-process reopen while comparing the complete expected draft, study and snapshot.
