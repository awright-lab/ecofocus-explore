# Shared-scale analytical heatmaps

Heatmap is now a selectable output for imported categorical counts/percentages and grouped numeric means/sums, as well as supported sample-question metadata. Existing report chart selection, guided creation, imported query editing and question journeys expose it. It renders recorded cells; it does not add a new estimator, survey inference or significance test.

One scale covers the complete result, including cells outside a bounded canvas or thumbnail preview. Percentages use0–100. Other metrics include zero; mixed signs use a symmetric domain. White marks observed zero, blue positive values, orange negative values. Unavailable cells are gray and explicitly labeled, not colored as zero. Every canvas/export cell prints its value and recorded base; color alone is not the evidence. Fixed quantitative colors intentionally do not inherit category/brand palette overrides, whose meanings differ. Row/column display aliases and selected label sizes remain supported.

The model supports100rows×50columns and rejects larger, missing, ambiguous, invalid or unsupported legacy results. A legacy imported mean without verified cell bases needs refresh. Counts cannot be negative and percentages cannot fall outside0–100. Extremely large finite signed values are normalized without subtracting opposite extremes. No raw result, source row, label dictionary or historical cache is modified.

Canvas rendering is bounded to50rows×12columns and explicitly marks partial previews. An accessible complete-table dialog provides search/paging and Escape/focus return through the existing table browser. Thumbnails show at most6×3cells, retain the complete-result scale and disclose partial previews. The shared SVG export reconstruction includes all cells, values, bases and scale context, or refuses a layout that cannot fit rather than clipping rows. Excel retains all analytical cells. PowerPoint routes heatmaps through the existing complete visual fallback; it does not substitute native bars. Fresh native PDF/PowerPoint/image rendering and OS downloads remain unverified.

Verification includes signed/zero/unavailable cells, shared-column colors, fixed percentage scale, inherited/sparse/duplicate inputs, maximum-size matrices, numerical extremes, aliases, invalid inputs, export fit refusal, focused complete-table interaction and201contrast-intensity checks. Cell text is tested against the4.5:1 threshold described in [W3C contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). This is a scoped computed-color check, not whole-application WCAG certification.

The actual App workflow selects Heatmap for an existing4×2count result from a synthetic1,000×30study, saves it, undoes/redoes and cold reopens with all recorded table/series data and original rows preserved. SVG and XLSX artifacts receive semantic/XML checks; automated UI checks use jsdom. No claim is made for native browser layout, touch, screen-reader/fullscreen acceptance, raster fidelity, live Snowflake or backend correctness. The React review skill was applied to the component changes. No service, dependency, security setting, production data, publication, merge or deployment is changed.

Original goal31 remains partial: this supplies a bounded heatmap workflow, while dot plots, small multiples, slope charts and their acceptance remain outstanding. Independent review is required before accepting this candidate.

Independent review corrections add conditional focus restoration when a focused matrix region disappears after a result becomes oversized or invalid. Focus moves to the persistent complete-table button only if the region owned it and no other control has taken focus; valid updates and unrelated focus are preserved. A real App regression defers the normal imported-query transport, runs the actual engine over a synthetic1,010×30study, replaces a cached2×2heatmap with101×2cells, and verifies focus and protection from background Delete/Backspace/arrow actions. The source study and stored layout remain unchanged.

Metric IDs must also match their declared number/percentage format before heatmap rendering or export. This prevents malformed percentage metadata from bypassing0–100range checks. SVG and Excel now apply the shared own-base validator across chart types: unweighted bases must be nonnegative safe integers; inherited, fractional or unsafe unweighted bases cannot be printed as sample sizes. Valid own weighted fractional totals remain supported and labeled as weighted totals. Invalid exports refuse with a recovery explanation rather than changing stored values; raw JSON remains available. Excel can still contain all valid cells when a matrix exceeds the heatmap drawing limit. These corrections do not establish native Office/browser acceptance or survey-weighted inference.
