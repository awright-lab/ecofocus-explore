# Ambiguous source-column mappings

The shared imported-field reader still prefers an exact own key, including an exact blank value. When the exact key is absent, a single case-insensitive match remains supported. Multiple own keys matching only by letter case now raise an explicit ambiguity error instead of choosing the first property.

The actual prior producer at `591b086f7b48d9a8f4e72683ec17b299402f0cd0` demonstrates the risk with 1,000 synthetic rows and restored metadata pointing to `amount`, while rows contain both `AMOUNT` and `Amount`. Reversing row-property order changes the selected mean from 15 to 150, despite identical logical key/value data. Both previous workspaces, source receipts and snapshots are frozen in the synthetic fixture. This is a restored-metadata/mismatched-mapping reproducer; ordinary CSV import generates exact column mappings, and an ordinary UI incident was not established.

Fresh analysis refuses ambiguous selected grouping, measure, breakout, filter or audience values. Numeric and category profiles show unavailable status rather than partial statistics. Background field preparation refuses before worker construction, and source-evidence refresh does not seal an arbitrary projection. Filter-choice inspection distinguishes an error from an empty set, retains the selected constraint, and blocks creation/update. Audience controls retain saved values with an unavailable-source label and refuse an unverified population preview. No guessed key is substituted and no row is treated as blank merely to conceal ambiguity.

Historical cached values, receipt hashes, raw workspace serialization and snapshots are preserved. A hash validates the recorded execution payload; it does not establish that an ambiguous mapping reflected the intended source column. No old receipt or number is silently rewritten. In the App regression, the old mean stays recorded and refresh is disabled until the user explicitly chooses the exact `Amount` field. That deliberate selection yields 150 and survives save/reopen without changing study rows or the old snapshot.

Thirty new regression cases cover exact and unique-fallback compatibility, property-order ambiguity, all selected analytical roles, later-row failure, profile/worker refusal, filter/audience UI recovery, source receipts, actual prior raw-byte round trips and the complete App workflow. Existing numerical formulas, parsers, storage protocol/schema version, exports and authoring command handlers remain unchanged. Only the common reader and its error presentation are changed; this is not universal validation of every research-tool data path or metadata authenticity.

Native browser/Worker/CSP, screen-reader/touch, live Snowflake and Office/download acceptance remain open. Source preparation errors preserve original data and cached results. No remote publication, merge, deployment, production, permission, credential, billing or security-setting change is part of this correction.
